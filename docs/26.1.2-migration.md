# Migrating to Minecraft 26.1.2

Machine Metrics `0.5.0` targets **Minecraft 26.1.2** on **NeoForge**. This page summarizes what changed from the earlier Minecraft 1.21.1 line for server operators, pack developers, and addon authors.

---

## Supported platform

| Setting | Value |
| :--- | :--- |
| Minecraft | `26.1.2` |
| Loader | NeoForge only (the Forge subproject was dropped) |
| NeoForge | `26.1.2.122` and newer |
| Java | `25` |
| ModDevGradle | `2.0.148` |
| Applied Energistics 2 | `26.1.13-beta` and newer |

Minecraft 26.1 requires Java 25 and ships unobfuscated official binaries. Parchment mappings are no longer used.

---

## For server operators

The server config gained two request-validation keys in this line:

```toml
[sync]
max_request_range = 12.0          # Max distance (blocks) a player may request telemetry for (1.0 - 64.0)
max_requests_per_second = 20      # Per-player request cap per second (0 = unlimited, 0 - 200)
```

Every telemetry request is now range-checked, loaded-checked, and rate-limited per player before sampling. Existing metric permission keys are unchanged. See the [Configuration Guide](configuration.md#server-config-configmachinemetrics-servertoml) for the full list.

## For addon and adapter authors

The NeoForge capability layer moved from the `IItemHandler` / `IFluidHandler` / `IEnergyStorage` family to the transfer-handler API. If you maintain an adapter against Machine Metrics internals, update your calls as follows.

### Block capabilities

| 1.21.1 | 26.1.2 |
| :--- | :--- |
| `Capabilities.ItemHandler.BLOCK` → `IItemHandler` | `Capabilities.Item.BLOCK` → `ResourceHandler<ItemResource>` |
| `Capabilities.FluidHandler.BLOCK` → `IFluidHandler` | `Capabilities.Fluid.BLOCK` → `ResourceHandler<FluidResource>` |
| `Capabilities.EnergyStorage.BLOCK` → `IEnergyStorage` | `Capabilities.Energy.BLOCK` → `EnergyHandler` |

### Handler methods

| 1.21.1 | 26.1.2 |
| :--- | :--- |
| `handler.getStackInSlot(i)` | `handler.getResource(i)` |
| `handler.getTankCapacity(i)` | `handler.getCapacityAsLong(i, resource)` |
| `handler.getFluidInTank(i).getAmount()` | `handler.getAmountAsLong(i)` |
| `storage.getEnergyStored()` | `handler.getAmountAsLong()` |
| `storage.getMaxEnergyStored()` | `handler.getCapacityAsLong()` |

### Identifiers and rendering

| Area | 1.21.1 | 26.1.2 |
| :--- | :--- | :--- |
| Resource identifier | `ResourceLocation` | `Identifier` (`Identifier.fromNamespaceAndPath(...)`) |
| GUI rendering | `GuiGraphics` | `GuiGraphicsExtractor` (`graphics.pose()`, `fill`, `outline`, `text`) |
| Input events | positional `mouseClicked(double, double, int)` | event objects (`MouseButtonEvent`, `extractRenderState(...)`) |

## Mod compatibility on 26.1.2

| Mod | Status | Notes |
| :--- | :--- | :--- |
| Applied Energistics 2 | Supported | Official 26.1.2 line, gated by `isAE2Loaded()` |
| Sophisticated Storage | Supported | Namespace-gated adapter, no compile dependency |
| Functional Storage | Supported | Drawer adapter via reflection |
| Storage Drawers | Supported | Drawer adapter via reflection |
| Jade / WTHIT / The One Probe | Supported | The HUD suppresses its duplicate title |
| Create | No official build | Kinetic inspector is fully reflective and inert when Create is absent |
| Mekanism | No official build | Chemical adapter is compile-decoupled and falls back to generic capability reads when absent |

The optional Mekanism API stub exists only at compile time. The shipped jar contains no `mekanism.*` or `appeng.*` classes; AE2 and Mekanism types are referenced only after their load check passes, so their absence never throws a class-loading error.

---

## Upgrading an existing world or server

1. Back up the world first.
2. Update NeoForge to `26.1.2.122` or newer and run the game on Java 25.
3. Replace the mod jar with the `0.5.0` NeoForge build for `26.1.2`.
4. Keep your `config/machinemetrics-client.toml` and `config/machinemetrics-server.toml`. Keys are unchanged except for the two new `[sync]` request-validation keys, which use safe defaults automatically.
